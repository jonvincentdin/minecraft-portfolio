# Record project facts

1. Read applicable AGENTS.md and context/MEMORY_WORKFLOW.md. Inspect the working tree, changed files, relevant source and actual check output. Do not trust an earlier completion claim without evidence.
2. Update context/PROJECT_FACTS.md with an absolute YYYY-MM-DD date and explicit timezone. Record the branch/commit if available; distinguish uncommitted changes and an absent HEAD. Never invent a commit or completed milestone.
3. Keep these sections: verified current state; accepted decisions and source; completed work with evidence; planned work; blockers/unknowns; next concrete steps. Attach repository paths and actual verification results to facts.
4. Preserve the distinction between the supplied vanilla reference and the planned React/Supabase application. Separate local draft persistence from shared publication, model files from verified browser rendering, and available skills from installed/connected MCPs.
5. Keep the snapshot short. Append milestone history to context/PROGRESS.md rather than endlessly expanding the current snapshot. Update CURRENT_STATE only when implementation evidence changes it.
6. Exclude secrets, private memories, fabricated owner content, transient logs and unverified estimates. Preserve useful decisions; supersede outdated claims explicitly instead of quietly erasing history.
7. Review the diff under the existing GitHub/permission policy. Report changed files, verification and remaining work. A snapshot does not complete a milestone by itself.
